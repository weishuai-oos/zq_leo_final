# T800 踝部组合任务

任务名：`T800_base-AnkleCombined`

该任务直接继承 `T800BaseEnvCfg`，从零开始训练，不读取 `T800_base` 或其他任务的 checkpoint。其余基础奖励、观测、动作、AMP和地形配置沿用 base；地形仍按项目当前配置使用 20% 平地及其余地形比例。

本任务组合三项改动：

- 目标平滑：`ankle_target_rate_l2 = -0.04`，`ankle_target_acceleration_l2 = -0.008`。
- 四个踝关节执行器：`Kp = 40`，`Kd = 1.2`。
- 支撑期默认姿态：使用 `ankle_support_joint_pose_l2`，权重 `-0.02`，默认姿态偏差按 0.1 rad 归一化，roll 权重为 pitch 的 2 倍，仅在对应脚接触支撑时计算。

## 训练提交

```bash
cd /srv/shared/home/xjh/workspace/zq_leo_final
mkdir -p logs/slurm
bash scripts/train_ankle_combined.slurm --dry-run
sbatch scripts/train_ankle_combined.slurm
```

脚本默认使用 2 张 RTX 3090、4096 个全局环境、seed 42、100000 次更新、每 500 次保存、4 天时限。输出文件为：

- Slurm stdout：`logs/slurm/T800_base-AnkleCombined-<jobid>.out`
- Slurm stderr：`logs/slurm/T800_base-AnkleCombined-<jobid>.err`
- TensorBoard和checkpoint：`logs/cusrl/T800_base-AnkleCombined/<时间戳>:T800_base-AnkleCombined_2gpu_seed42/`

脚本会拒绝非空的 `CHECKPOINT` 环境变量，避免误用续训参数；训练使用 base 的初始学习率 `1e-3` 和原有自适应学习率调度，不使用 ankle continuation 的 warmup 或学习率上限。三项改动从第一次采样起生效。

之后若需要断点恢复，可在训练入口 `scripts/cusrl/train.py` 中传入该任务自身的 `--checkpoint`，并设置更大的绝对 `--max_iterations`。恢复和 Play 会核对保存的任务、PD 和奖励配置，拒绝使用 base 或旧四个续训任务的 checkpoint。

## 109 可视化

训练完成后，在 109 的 `/home/xjh/workspace/zq/zq_leo_final`、conda 环境 `leo` 中运行：

```bash
cd /home/xjh/workspace/zq/zq_leo_final
conda activate leo
python scripts/cusrl/play.py \
  --task T800_base-AnkleCombined-Play \
  --load_run 'logs/cusrl/T800_base-AnkleCombined/<时间戳>:T800_base-AnkleCombined_2gpu_seed42/ckpt/ckpt_100000.pt' \
  --num_envs 1 --device cuda:0
```

将上面的时间戳和 checkpoint 编号替换为实际文件，并先复制该模型到 109。`--load_run` 也接受运行目录，此时自动选择目录中的最新 checkpoint。无图形界面短测可以附加 `--headless --no-debug-vis --auto_command_test boxing_practical`。

默认踝角的弱约束不保证脚掌始终平行地面；脚掌方向还受髋、膝和地形影响。新组合是否优于已有 Smooth，需要训练后按相同指令检查实际踝角高频量、脚滑、速度跟踪和摔倒情况。
