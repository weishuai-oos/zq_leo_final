# T800 踝部组合第二版续训

任务名：`T800_base-AnkleCombinedV2`；可视化任务：`T800_base-AnkleCombinedV2-Play`。

本版直接继承 `T800AnkleCombinedEnvCfg`，从 Combined 完整 checkpoint 续训。目标是同时验证较大阻尼、较小接触偏移，以及针对实际踝部运动的强惩罚。原 Combined 任务和 checkpoint 的使用方式保留。2026-11-07 按用户要求将 Slurm 默认新增更新数改为 40000，并以稳定性与鲁棒性短测选择续训起点。

## 改动与依据

| 项目 | Combined | CombinedV2 |
|---|---:|---:|
| 四个踝关节 Kp | 40 | 40 |
| 四个踝关节 Kd | 1.2 | 2.0 |
| 机器人碰撞体 contact offset | 随机 6–14 mm | 固定 2 mm |
| 目标变化率权重 | −0.04 | 保留 −0.04 |
| 目标加速度权重 | −0.008 | 保留 −0.008 |
| 原控制周期实际踝加速度权重 | −0.001 | 保留 −0.001 |
| 支撑期默认关节姿态权重 | −0.02 | 保留 −0.02 |
| 新增物理子步实际踝加速度 | 无 | −0.02，见下方归一化公式 |
| 新增稳定支撑期脚掌角速度 | 无 | −0.2，roll 强于 pitch |

2 mm 设置通过原有 startup 事件作用于机器人碰撞体；地面配置不变，不能将其理解为碰撞体对的接触生成距离就是 2 mm。rest offset 保留资产设置，109 实际读回为 0。没有修改脚底碰撞几何。地形、观测、动作、AMP、其他关节 PD 和原有目标处理沿用 Combined，平地比例仍为 20%。

使用了此前在 109 留存的 Combined95000 数据做定标，未为定标反复长测：4 个环境、平地、seed42，0.5 和 1.0 m/s 两段。原实际踝加速度罚项平均约 −0.00063 / −0.00152，而两项速度跟踪正奖励约 2.42 / 2.35；50 Hz 端点差分得到的加速度均方只有 200 Hz 采样的约 13% / 14%。因此新增逐物理子步统计，而不是只放大原罚项。

在 Kd2.0 + 2 mm 的数据上，实际踝加速度绝对值的 P95 约为 130 / 236 rad/s²；稳定支撑期足部局部 roll 角速度 P95 约为 3.66 / 5.38 rad/s，pitch 约为 0.51 / 1.04 rad/s。后两个数由姿态差分近似得到，用于选择初始门限；正式实现直接读取物理引擎的足部角速度。既有短测中 Kd2.0 + 2 mm 使两段合并的实际踝角 8–40 Hz RMS 下降约 15.8%，仍未消除抖动。

数据及口径见 [踝部抖动复审与奖励改进建议](validation/踝部抖动复审与奖励改进建议_2026-11-07.md) 和 `logs/validation_ankle/marker_reward_probe_20261107_2243/`。这些是设计依据，不能当作 V2 续训后的效果。

## 新增惩罚的计算

控制频率 50 Hz，物理频率 200 Hz。每个控制周期先收集 4 个连续物理子步，再计算奖励；每个子步分别平方后取平均，防止周期内部的往返变化在端点相消。重置后的首步从重置后的真实速度开始，不把重置跳变计入加速度。

1. **实际踝关节加速度**：四个 ankle pitch/roll 都计算，支撑期和摆动期都生效。

   `a = (dq_now - dq_previous) / 0.005`

   `cost_acc = mean(min(max((abs(a) - 100) / 100, 0), 20)^2)`

   对 4 个关节、4 个子步取平均，最终权重 −0.02。100 rad/s² 内为死区；归一化误差上限 20。此项也可能惩罚快速的正常运动或触地冲击，不等于单独提取了高频抖动。

2. **稳定支撑期脚掌角速度**：惩罚足部局部坐标的 roll/pitch 旋转，允许绕足面法向的 yaw。没有直接强制脚掌相对世界水平，以保留斜面适应能力。

   `cost_roll = min(max((abs(omega_roll) - 0.5) / 1.0, 0), 20)^2`

   `cost_pitch = min(max((abs(omega_pitch) - 1.0) / 2.0, 0), 20)^2`

   对两轴、两脚和 4 个子步取平均，只有对应脚满足支撑门控时计入，最终权重 −0.2。相同超出死区的角速度下，roll 的平方代价是 pitch 的 4 倍。

门控读取当前子步的竖直接触力：50 N 进入，10 N 退出；累计承载 30 ms 后生效，放行最初落脚过渡。最长 20 ms 的短暂失载保留接触年龄，但失载期间不累计年龄、不计算脚掌旋转惩罚；更长缺口重新计时。

以上为未乘控制周期 dt 的加权奖励率。RewardManager 统一乘 0.02 s，不重复乘时间。新奖励从零开始，在新增的前 1000 次更新中线性增加到完整权重。Kd 与接触偏移从第一步直接生效；原目标平滑与弱姿态项始终保持原权重。

这两个门限刻意允许一部分小幅运动，不承诺消除所有残余抖动。关节默认角不等于脚掌平行地面，因此没有进一步加重原默认姿态惩罚。

## 109 可视化与判断

相关代码已同步至 109。取得正式训练的 V2 checkpoint 后，在 `leo` 环境直接运行普通命令：

```bash
cd /home/xjh/workspace/zq/zq_leo_final
conda activate leo
python scripts/cusrl/play.py \
  --task T800_base-AnkleCombinedV2-Play \
  --load_run '/绝对路径/ckpt_103000.pt' \
  --num_envs 1 --device cuda:0 --free_camera --camera_env 0
```

V2 Play 要求 V2 checkpoint，不能直接把原 Combined 文件当成 V2。普通 Play 使用完整奖励配置，但不会训练更新策略。

建议先比较新增 3000 / 6000 次后的模型，不必等到全部 40000 次。用相同 seed、地形、速度指令比较实际踝角及脚掌 roll/pitch 的高频量、速度跟踪、滑脚与摔倒。训练日志新增：

- `AnkleV2/physics_acceleration_cost` 与 `physics_acceleration_rms_rad_s2`。
- `AnkleV2/support_foot_rotation_cost`，以及 `support_foot_roll_rms_rad_s`、`support_foot_pitch_rms_rad_s`。
- `AnkleV2/support_fraction`：每个物理子步满足门控的脚数比例，范围 0–1；单脚稳定支撑时约 0.5。它包含 30 ms 过渡过滤，并非原始接触占比。

若新成本下降而支撑占比明显下降、步子变碎或速度跟踪变差，不能判断为改善。因为这是 PD、接触和奖励的组合验证，即使成功也不能单凭这一组确定各改动分别贡献多少。
