## 新版：T800_base-ImpactV2Plus

Plus直接基于基础任务配置，实现在 `tasks/t800_impact_v2_plus/`，不导入旧Impact或踝部实验任务。
它仍是一套LSTM策略；恢复阶段只改变训练奖励和终止判断，不给部署策略增加击打标志或新观测。
网络、动作和AMP维度不变。踝Kp40/Kd2.0、2毫米接触偏移、正常行走防抖权重、击打分布、
80%平地/20%水平障碍均沿用ImpactV2。

恢复过程分为“先稳住支撑，再回到拳架”：

- 近期受击且实际失衡，或出现明显身体失衡/异常支撑时进入恢复；正常换速度指令本身不触发。
- 恢复期减轻默认姿态、拳架和AMP约束；踝目标平滑、实际加速度、支撑脚转动、重落脚和滑动
  只适度减轻。关节物理限位、力矩限制和PD保留，正常阶段不降低防抖权重。
- 脚侧、手、肘、膝短暂触地不立即重置；记录事件，并要求脱离异常支撑后才算恢复。
- 物理稳定至少保持0.25秒，再用0.5秒逐步恢复拳架约束。恢复期限2.5秒，连续受击不续期。
  持续倒地或恢复超时终止训练回合；超时和倒地分别记录。
- 这版主要学习失衡后的救回，不等于已经学会完全躺倒后的起身。

## V2与Plus统一测评标准

新比较显式使用 `evaluate_impact.py --protocol recovery_v1`；旧规则保留为 `--protocol legacy`。
新旧规则的数字不能混成一列。两版使用相同的环境数、固定指令、初始随机种子、物理参数及
预生成击打计划，报告含计划哈希和实际施加击打；某环境先倒下不会改变其他环境的击打。

| 项目 | recovery_v1定义 |
|---|---|
| 真正倒地 | 胸/骨盆/头持续触地0.15秒；或根部离地低于0.45米/身体倾斜超过80°持续0.30秒 |
| 临时撑地/翻脚 | 单独记录手膝触地、脚侧触地及持续时间，不直接算倒地，也不算恢复成功 |
| 重新稳定 | 根高≥0.75米、身体倾斜<0.18弧度、横滚俯仰角速度<1弧度/秒、平面速度误差<0.55米/秒，且无异常支撑，保持0.25秒 |
| 回到拳架 | 稳定基础上，手臂相对拳架参考姿态的平均绝对误差<0.25弧度，再保持0.25秒 |
| 恢复超时 | 该次击打起2.5秒内未完成恢复；窗口内后续击打不续期，单列为未恢复，不改称真正倒地 |
| 测试结束 | 恢复窗口尚未结束的事件标记为截尾，单独计数，不算已恢复，也不冒充超时 |

比较顺序：先看真正倒地率和未恢复率，再看恢复及拳架返回耗时，最后检查无击打走路和踝防抖。
无击打、常规击打、压力击打分开；至少固定种子42和43，每种48环境、20秒，按12个固定指令报告，
同时检查前后左右、旋转及不同受击部位，不能只看平均总奖励或存活率。
恢复后的帧必须来自同一物理回合；自动重置后的直立姿势不能记成恢复。
受击后始终没有失衡的事件记为抵抗成功（resisted），与失衡后救回（recovered）分别统计。
训练恢复计时从实际失衡触发起；统一测评从击打起计时，便于不同策略按同一时刻比较。

建议首轮验收线：无击打不新增倒地，速度跟踪和实际踝抖动相对V2不恶化超过约10%；压力工况
在相同计划中减少倒地/未恢复，且常规工况没有明显退化。这个10%是试验筛选线，不是硬件保证，
小样本接近的结果应扩充种子后再选模型。以上高度/姿态阈值也应结合Play确认，不能只凭分数放行。

测评命令（分别替换任务与模型路径运行，保留相同参数）：

```bash
python scripts/cusrl/evaluate_impact.py --task T800_base-ImpactV2Plus-Play \
  --checkpoint /absolute/path/to/plus_checkpoint.pt \
  --protocol recovery_v1 --num_envs 48 --duration-s 20 --seed 42 \
  --impact_mode stress --output /tmp/impact_plus_stress_seed42.json --headless --device cuda:0
```

测V2时只替换任务为 `T800_base-ImpactV2-Play` 并换V2模型；无击打/常规工况对应
`--impact_mode off/common`。测评原始数据可放 `/tmp`，仅保留需要的简短JSON报告，不采大量视频或逐帧数组。

独立脚本默认申请 2 张 RTX 3090，4096 个总环境，新增 40000 次更新，每 500 次保存。
从 `ckpt_85500.pt` 开始时，默认最终更新编号为 `125500`。
正式执行前依次检查 CUDA、构建 2 个环境、严格恢复模型并短暂步进实际外力。
随后检查足底有真实地面过滤支撑力，并将机器人放倒，要求 0.5 秒内因非足触地终止。
默认新增预算是起始试验预算，不是收敛保证。当前实现没有自动提交作业。
日志和新 checkpoint 写入 `logs/cusrl/T800_base-Impact/`，不覆盖第一阶段运行目录。

`--additional_iterations` 表示在传入 checkpoint 编号基础上增加的更新数；
`--max_iterations` 仍表示最终总编号，两者互斥。从本阶段 checkpoint 恢复也使用同一任务，
课程、阶段起点和学习率上限随 checkpoint 恢复，不重复暖身或再次减半学习率。
Slurm 可用 `ADDITIONAL_ITERATIONS` 或 `MAX_ITERATIONS`，以及
`NUM_ENVS`、`SAVE_INTERVAL`、`SEED`、`RUN_NAME` 覆盖相应参数。
训练恢复要求扰动 RNG 的设备类型一致；评估或导出允许从 GPU 检查点切换到 CPU，
此时保留阶段进度，但重新生成确定性的评估随机流，不承诺跨设备逐次命中完全一致。

2026-11-04 起，训练与 Play 的压力工况均改为单击。恢复旧的压力连击 checkpoint 时，
训练入口需显式传 `--impact-single-hit-migration`，Slurm 对应
`IMPACT_SINGLE_HIT_MIGRATION=1`。此选项只接受原压力组合概率 0.70、上限 5 击的已知旧签名，
不会跳过其他配置校验；保留模型、优化器、阶段进度和学习率上限，在新 checkpoint 中记录迁移。
新 checkpoint 后续正常恢复，无需再次指定迁移选项。Play 自动识别这一种旧配置。
中途改变分布不影响已经运行的进程，需要从已保存 checkpoint 重启。
例如原目标为 125500，重启时使用 `MAX_ITERATIONS=125500`，避免再次追加 40000 次。

## 与第一阶段的兼容契约

| 接口 | 维度/约定 |
|---|---|
| Actor | 84，原观测顺序 |
| Critic | 87，原观测顺序 |
| 采样动作 | 25，原 DFS 顺序、scale 和 default offset |
| AMP policy/reference | 96，原两帧历史和特征顺序 |
| 网络 | Actor/Critic 各两层 256 LSTM，原 AMP 512/256 MLP |

头部槽位保留，改变它们的输入语义。Actor 的头位置输入固定为实际 nominal
`(0.052337, 0.621251)`，头速度和历史头动作固定为零；Critic 的头相对位置/速度、
AMP 的 policy/reference 头相对位置/速度均为零。屏蔽在归一化之前执行，
关节观测噪声也在最终屏蔽之前添加。头位置/速度为 NaN/Inf 不会进入网络。
其他身体或核心传感器异常不在这个头部隔离保证之内。

PPO 保存实际采样的 25 维动作和相应 log probability，执行时独立覆盖头目标；
不能先修改采样动作再假装沿用原 log probability。健康头维持 nominal 姿态，
弱化或失能头不参与策略控制。固定头槽位不代表真实机械头被固定。
头部姿态奖励已移除，其余身体奖励不读取异常头反馈。

恢复入口先检查 Actor、Critic、归一化、AMP hook、优化器参数顺序及状态形状，
加载后再逐值核对，避免 CusRL 的告警式宽松加载留下随机初始化状态。
仅规范化已知 DDP/compile 包装造成的参数名称差异。
首次进入第二阶段，以 checkpoint 的**实际学习率的一半**作为学习率上限，
后续 KL 调度可降低、不能越过该上限；同步调度器比例，保存后继续沿用。
没有改变网络维度，因此未读取 MIRLab 的维度迁移实现。

## 外力和课程

参数集中在
`source/t800_lab/t800_lab/tasks/t800_impact/impact_config.py`。
峰值来自已有实测描述，以下采样权重、脉宽、冲量和恢复阈值是待标定的工程初值。

| 项目 | 默认值 |
|---|---|
| 物理步/控制步 | 5 ms / 20 ms |
| 暖身 | 本阶段前 500 次更新无击打、保持健康头，先适应头部隔离 |
| 渐进 | 接下来 5000 次更新增加力幅和压力场景概率 |
| 最终 episode 分组 | 无击打 25%，常见 65%，压力 10% |
| 来袭方位 | 正面/斜前 60%，侧面 35%，背面 5% |
| 常见峰值 | 40–300 / 300–900 / 900–2000 N，带内概率 35% / 40% / 25% |
| 压力峰值 | 1600–5000 N，受部位冲量上限进一步截断 |
| 脉宽 | 头 12–35 ms；手臂 18–60 ms；躯干/骨盆 25–80 ms；腿 25–90 ms |
| 常见组合概率 | 30%，组合为 2–3 击 |
| 压力击打 | 每组只有 1 击；训练和 Play stress 一致 |
| 击打间隔 | 常见组内 150–500 ms；各组结束后 2–5 s，首次 1.5–3 s |
| 地形 | 80% 平地、20% 水平柱状障碍，保留原柱体难度课程 |

方位沿用第一阶段的 37° 战术正前方向，正面表示对手所在方向，外力朝向机器人。
一次击打开始后，方向固定在世界坐标；机器人转动不会使来袭方向跟着转动。
每次随机一个实际身体 link 和该 link 坐标系中的偏心点。
每个 5 ms 步使用半正弦脉冲的解析积分除以步长得到平均力，
因此短脉冲不会因控制频率而漏掉，也不会错误地持续一个完整 20 ms 控制步。
局部力矩按 `r × F` 合成，再写入 IsaacLab 的 instantaneous wrench composer；
不使用本地 2.3.2 有已知坐标缓存问题的永久世界坐标施力路径。

持续时间和峰值同时受部位冲量上限约束。例如请求 5000 N 不等于每个部位
都会实际施加 5000 N；日志分别记录采样/实际步平均峰值及冲量。
当前力是简化的等效来袭载荷，不包含真实拳脚的接触体积、阻挡、勾挂和绊倒。

头部主训练为 15% 被动失能、10% 弱驱动、其余健康，按 episode 采样，
故障在 2–8 s 延迟后出现；前 500 次更新保持健康。
无头 URDF 作为独立验证模式，23 个实际身体关节仍映射到原 25 个逻辑槽位。
被动头和无头是两种不同动力学；电线悬挂头、结构断裂没有建模，
不能用基础质量随机化宣称覆盖这些情况。

## 奖励与判定

保留倒地惩罚、姿态稳定及关节/脚踝限位约束。移除足部腾空时长奖励，
不设置“挨打就迈步”的奖励。受击且实际倾角、角速度或命令相对速度误差
超过阈值时，短暂放宽软跟踪、抱架和动作平滑成本，同时降低该 transition 的 AMP 风格奖励。
默认最多 1.2 s，稳定后退出；连续命中不会无限延长同一个宽松窗口，重新触发需先稳定。
轻触且未失稳时继续原要求。稳定指标不能因为“短暂偏离”而被屏蔽。

倒地由每个碰撞身体的**地面过滤接触**检查，避免把自身接触或未来的独立对手/围笼接触
作为触地；非足身体使用四个物理步历史。足部还检查当前接触点和足面朝向，
逐物理步保留侧足触地结果。接触点是引擎的平均点，足底边缘判定仍是近似。
水平柱体目前与地面合并成同一个网格，所以身体碰到代表倒地对手的柱体也会保守判倒地。

2026-11-04 修正了地面过滤目标：必须指向实际带 CollisionAPI 的
`/World/ground/terrain/mesh`，旧路径 `/World/ground/terrain` 是父 Xform，
在 GPU PhysX 中会导致过滤接触力始终为零，漏掉倒地。启动时会验证碰撞 prim，
Slurm 冒烟还验证实际支撑力和强制倒地重置。修复前的倒地率与相关奖励日志不能用于证明不倒地。

目前训练没有物理围笼。日志的 `arena_root_margin_m` 只按内切圆直径 8 m 的正八边形
计算根部离边界的余量，不是围网碰撞，也不是全身在笼内的保证。
近笼碰撞、网面柔顺性、软垫压缩及真实拳脚碰撞需要后续单独验证。
没有添加未经规则要求的倚网惩罚。
