# 脚踝防抖迁移指南

供行走、动作追踪项目参考。依据T800本次实现与2026-11-09测试整理。核心做法在环境和控制侧，不依赖AMP判别器。

**本次明显改善了支撑期脚掌摇摆，但没有证明所有踝关节高频变化都已消失。** 有效的是PD、接触设置、目标平滑和真实运动惩罚的组合；动作追踪适配部分是迁移建议，尚未在同事项目验证。

## 1. 先确认抖的是哪一层

同时记录最终下发的关节目标、实际关节角/速度、脚掌姿态/角速度和接触力，区分目标抖、实际关节振荡、脚掌触地后摇摆。

- 核对仿真、Play、部署的关节映射、默认姿态、动作尺度、控制频率、执行器类型、力矩限幅、延迟和实际Kp/Kd。配置文件中的数值最好从运行时再读回。
- 检查真正启用的碰撞体。本次T800脚底小球只是显示元素，实际碰撞是盒子；删除显示球不能解决接触问题。
- 动作追踪先检查重定向参考是否已经有脚抖、接触时序错误或插值跳变。参考本身有问题时，先处理参考。

**目标平滑不等于脚掌稳定；踝偏离默认角也不一定异常。** 保持脚掌贴地时，踝角可以随膝、髋运动而变化。

## 2. 本次采用的设置

只针对左右踝pitch/roll四个关节及两只脚，不把新增惩罚加到全身。

| 项目 | T800采用值 | 迁移时注意 |
| --- | --- | --- |
| 踝Kp/Kd | 40 / 2.0；续训前为40 / 1.2 | 其他机器人先短测阻尼，不能照搬2.0 |
| 机器人contact_offset | 随机6–14mm改为固定2mm | 地面设置未改，rest_offset实际为0 |
| 目标变化率惩罚 | 权重−0.04，归一化尺度4rad/s | 针对最终关节目标，不是未经缩放的网络动作 |
| 目标加速度惩罚 | 权重−0.008，归一化尺度80rad/s² | 动作追踪优先考虑参考残差，见第4节 |
| 新增实际踝加速度惩罚 | 权重−0.02，逐物理步计算 | 避免只看控制周期端点而漏掉往返振荡 |
| 新增稳定支撑脚掌旋转惩罚 | 权重−0.2，roll强于pitch | 主要约束承重后脚掌左右、前后摇摆 |

contact_offset是接触生成距离参数，不是把鞋底抬高同等距离。需要检查碰撞体对两侧的contact/rest offset；2mm是本次机器人侧设置，不是通用最优值。本次没有更换足底碰撞几何。

另保留了原有弱支撑期默认姿态项（−0.02），它不是V2新增的核心做法；动作追踪不宜直接照搬默认姿态约束。

## 3. 两项核心惩罚怎么实现

本项目物理步长 `dt_phys=0.005s`，控制周期 `dt_ctrl=0.02s`，每次策略动作经历4个物理子步。定义：

```text
H(x) = min(max(x, 0), 20)^2
```

### A. 惩罚真实踝加速度

每个物理子步读取仿真实际速度，计算：

```text
a = (dq_now - dq_previous) / dt_phys
C_acc = mean_物理子步,四踝 [ H((abs(a) - 100) / 100) ]
r_acc = -0.02 * C_acc
```

单位为rad、s；100rad/s²以内为死区。**先对子步的超限量平方，再平均**，不能先平均加速度再平方，否则正负往返会相消。此项作用于支撑和摆动两个阶段，也可能惩罚正常快速运动，不能把它当成纯高频滤波器。

### B. 惩罚稳定支撑时的脚掌旋转

把脚部世界角速度转换到脚底局部坐标；这里 `R_sole_world` 是从脚底坐标到世界坐标的旋转矩阵：

```text
omega_local = R_sole_world.T @ omega_world
C_foot = mean_物理子步,两脚 [
    support_mask * (
        H((abs(omega_local.roll)  - 0.5) / 1.0)
      + H((abs(omega_local.pitch) - 1.0) / 2.0)
    ) / 2
]
r_foot = -0.2 * C_foot
```

角速度单位rad/s；yaw不惩罚。同等超出死区的幅度下，roll平方代价为pitch的4倍。先确认项目的脚底坐标：这里局部X/Y对应roll/pitch、Z沿脚底法线；若刚体坐标不同，先转换到真正的脚底坐标。

`support_mask`对每只脚分别维护，读取**当前物理子步**的竖直接触力Fz：

- Fz≥50N进入支撑，已进入后Fz≤10N退出；其他机器人按自身承重重新定标。
- 累计接触30ms后才计算旋转惩罚，放行初始落脚过渡。
- 最长20ms的短失载保留接触年龄；失载期间不累计年龄、不计算惩罚，更长缺口清零年龄。

这约束的是脚掌旋转速度，没有强制脚掌始终相对世界水平，因此保留了斜面适应能力。

### 接入时容易出错的四点

1. 每次控制步开始保存当前真实dq并清空本周期累计；在已有物理循环的**仿真状态、接触力刷新后**采样，计算奖励前收齐全部子步。接触传感器也应按物理频率更新。
2. 重置时清接触年龄、目标历史；下一步以重置后的dq作差分起点，不把重置跳变当加速度。奖励已计算的当步累计不能被提前清掉。
3. 两项公式给出奖励率。本项目RewardManager会统一乘 `dt_ctrl`，不要重复乘时间；迁移时核对自己的奖励框架。
4. 目标平滑项另按控制周期计算：`v_des=Δq_des/dt_ctrl`、`a_des=Δ²q_des/dt_ctrl²`，分别使用 `−0.04*mean((v_des/4)^2)`、`−0.008*mean((a_des/80)^2)`。重置后的差分历史需要有效性掩码。

## 4. 动作追踪项目要改什么

**保留正常参考运动，重点抑制实际运动相对参考的多余振荡。** 以下需要在同事项目单独验证：

| 场景 | 建议适配 |
| --- | --- |
| 动作为参考姿态上的残差 | 若 `q_des=q_ref+scale*action`，优先平滑 `q_des−q_ref`；直接重罚完整目标可能压制参考本身的快速变化 |
| 参考要求踮脚、滚脚、转身 | 脚掌项考虑 `omega_error_local=R_sole_world.T@(omega_actual_world−omega_ref_world)`，再取roll/pitch；不能一律要求实际角速度为零 |
| 参考包含踢腿、跳跃、快速摆腿 | 实际加速度项先在合适支撑阶段使用，或改为相对参考的加速度误差；不能照搬本次全阶段死区和权重 |
| 参考有接触标签 | 结合参考支撑阶段与实测接触，保留接触时序/动作跟踪奖励，防止策略通过少着地绕过防抖惩罚 |

参考角速度、加速度必须和仿真使用相同时间、频率、关节顺序及坐标系；运动重定向、朝向对齐后再比较，差分和插值处理不好会制造新噪声。不要直接差分欧拉角跨越±π的位置来构造参考角速度。

不建议直接把踝锁到默认角：默认踝角不等于脚掌水平，也可能与参考动作冲突。追踪奖励、动作误差和接触时序仍是主任务，防抖只是正则项。

## 5. 怎么训练、怎么判断有效

先在同一checkpoint上短测PD、接触参数变化，再增加奖励续训。本次100000→140000，新增两项奖励在前1000次更新由0线性增加到完整权重；PD与接触设置从第一步生效。保留策略、价值网络、归一化、优化器状态，AMP项目还保留判别器；学习率上限设为源模型当前值的0.5倍。

这些是本次续训做法，不是其他项目必须照抄的训练预算。已有策略可以先续训验证，不必因为“已经学会抖动”就立即从头训练。若之后从零训练，直接使用最终验证过的动力学和任务定义，并重新检查奖励预热和学习率设置。

短测用相同初始条件、指令或参考片段，至少覆盖静止、慢走、快走和落脚。动作追踪另保留动态片段，确认动作没有被压平。记录：

- 实际踝角/速度、最终目标、支撑期脚掌roll/pitch角速度、滑移和接触占比；区分稳定支撑、落脚过渡、摆动阶段。
- 行走速度误差或动作追踪误差、摔倒和力矩饱和，避免靠降速、少着地或不做动作换取“平滑”。
- 高频指标按物理频率采样。本次200Hz采样、比较8–40Hz；50Hz采样无法可靠测量40Hz。频段需适配步态，不能把正常动作谐波都视作故障。

本次1m/s平地短测如下；原始100000用Kd1.2、contact_offset随机6–14mm，V2用Kd2.0、2mm。这是组合效果对照，不能拆分各项贡献：

| 指标 | 原始100000 | V2 118500 | V2 140000 |
| --- | ---: | ---: | ---: |
| 稳定支撑脚roll角速度RMS（rad/s） | 1.805 | 0.401 | 0.207 |
| 实际踝角8–40Hz RMS（°） | 0.525 | 0.399 | 0.503 |

脚掌摇摆明显下降，但最终模型的踝角高频幅度没有持续下降。**选择模型要结合Play、任务质量和多个指标，不能只看奖励或最后一个pt。** 这些是短时仿真结果，尚未证明真机消抖。
