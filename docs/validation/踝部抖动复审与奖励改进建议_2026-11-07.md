# T800 踝部抖动复审与奖励改进建议

日期：2026-11-07。范围：当前 T800_base / AnkleCombined 源码、109上的官方 engineai_rl_lab 副本、Combined95000 的固定平地短测。本报告接续[此前碰撞与官方PD核对](踝部碰撞与官方PD核对_2026-11-07.md)。未修改训练、Play或部署源码，未提交训练。

## 结论

1. **PM01_EDU 使用 Q50H 的说法，在所查官方工程中没有依据。** PM配置仅声明Q90/Q25，踝为Q25；不能将这一配置事实扩大为真实硬件BOM结论。
2. **Kd2.0有依据、有部分收益，但仅改Kd不足以支持再投入一次完整长训。** 官方T800 Tracking用40/2；本轮Kd2与机器人contact_offset2mm组合使踝8–40Hz RMS下降15.8%，仍有抖动。
3. **小球是主因的猜测进一步受到反证。** 小球无碰撞API；本轮再移除小球及其独立固定刚体、将质量和惯量合并到父link，抖动没有改善。不能把可视化球体误认为支撑碰撞面。
4. **目前最值得修正的是实际稳定性奖励的定义和尺度。** 当前实际踝加速度在50Hz末帧差分，既不累计全部200Hz物理子步，实际代价也非常小；Combined主要加强了目标平滑。
5. **严厉惩罚有可能进一步改善，不能保证消除。** 直接严罚默认踝角、所有踝速度或目标变化，会和落脚、蹬地及速度跟踪冲突。应先针对稳定支撑期脚部转动和子步实际振荡，再校准实际奖励贡献。

独立审查：code-reviewer=COMMENT，architect=WATCH，合并结论COMMENT。未发现能够直接解释抖动的关节索引错配、奖励历史未重置或PD未生效错误；尚未定位唯一根因。

## 小球、接触偏移与本轮三组短测

当前URDF小球半径2cm，仅visual，球底比真实足底box低约2cm。真实碰撞是 `LINK_ANKLE_ROLL_L/R` 下的box，运行时再次检查两球均无CollisionAPI。

为排除轻小固定link的间接影响，本轮临时URDF仅去掉 `LINK_FOOT_L/R` 与 `J_FIXED_FOOT_L/R`；将每侧1g质量、质心和惯量按平行轴定理并入父ANKLE_ROLL。保留所有原有碰撞体、关节自由度及PD。运行时检查：DOF名称、初始/默认关节位置、armature、材料、原contact/rest offsets一致；总质量浮点读回误差小于4e−7kg。仅两处FOOT刚体消失。

接触偏移核对：

- 当前 `tasks/t800_base/env_cfg.py:516–524` 启动时将机器人碰撞体contact_offset随机为 **6–14mm**；本轮读回约6.034–13.944mm。机器人rest_offset读回为0。
- 地面 `/World/ground/terrain/mesh` 的contact/rest offset没有author值，运行时USD返回 **−inf自动值标记**。安装版PhysxSchema明确说明contact默认由仿真根据形状尺寸选择，rest由仿真选择，刚体默认rest为0。**本轮没有取得地面底层PhysX shape的有效contact数值，不能说地面为0，也不能直接套用通用PhysX的2cm默认。**
- 因此，本报告“2mm”一直指机器人一侧的设置，不是机器人与地面成对接触距离为2mm。
- 接触生成距离取双方contact_offset之和；rest_offset决定静止表面间距。减小contact_offset不会将box变成球，或直接使机器人下沉同样距离；过小也可能增加漏接触/穿透风险，应结合物理步长验证。[PhysX官方说明](https://nvidia-omniverse.github.io/PhysX/physx/5.4.1/docs/AdvancedCollisionDetection.html#tuning-shape-collision-behavior)
- 本地schema证据：Isaac Sim安装目录 `extscache/omni.usd.schema.physx-107.3.26+107.3.3.lx64.r.cp311.u353/plugins/PhysxSchema/resources/generatedSchema.usda:516–536`。

协议：同一Combined95000，seed42、4环境、固定平地，站2秒→0.5m/s走8秒→1m/s走8秒→站2秒；200Hz连续4000帧，分析4–10s及12–18s。三组均无摔倒终止或时间截断。新基线所有物理记录数组与上一轮逐元素一致。

## 代码复审中最有价值的四项发现

### 1. 实际运动代价太小，且计算口径会抵消物理子步变化

`tasks/t800_base/ankle_stable_mdp.py:92–124` 每控制步读取末帧踝速度，计算 `(v_now-v_previous)/0.02`；`env_cfg.py:429–432` 权重−0.001，除以80rad/s²后平方并平均四关节。Combined未加强此项，只加强目标rate/acc。

复算本轮基线：

| 指标 | 0.5m/s | 1m/s |
| --- | ---: | ---: |
| 每5ms速度差分的加速度RMS，rad/s² | 173.776 | 260.634 |
| 每20ms末帧差分的加速度RMS，rad/s² | 63.726 | 98.559 |
| 后者均方 / 前者均方 | 13.45% | 14.30% |
| 实际踝加速度加权奖励率 | −0.000635 | −0.001518 |
| 目标rate+acc加权奖励率 | −0.022176 | −0.035441 |
| 支撑默认踝姿态加权奖励率 | −0.023447 | −0.022825 |
| 两项速度跟踪正奖励率 | +2.42126 | +2.35123 |

实际踝加速度成本仅上述跟踪正项的0.026%/0.065%。这些是已加权但未乘环境dt的奖励率，进入环境总奖励再乘0.02；AMP另有奖励，不能把此表当完整PPO目标。

200Hz数据每4帧最后一帧与50Hzepisode速度逐元素一致，按代码重算奖励与记录吻合。现有计算先平均20ms区间加速度再平方，正负子步变化可以相互抵消；应考虑每物理子步计算平方后累计/平均。

限制：25–40Hz只占8–40Hz踝角能量的6.88%/4.43%，不能说“主要抖动都高于25Hz、50Hz完全看不见”。加速度均方差异还包括更高频碰撞尖峰，不全等于肉眼看到的抖动。调整奖励是否有效仍需训练验证。

### 2. 默认踝角不等于脚掌平地，也不等于不摇晃

`tasks/t800_ankle/mdp.py:18–29` 仅罚踝相对默认角度，roll权重2、pitch权重1；没有足部世界角速度、足面姿态或地面法向。`env_cfg.py:292` 的flat_orientation项约束根部。滑脚项约束足部XY线速度，也不能替代足部角速度。

数学反例：取当前整套名义姿态、左右踝pitch=−0.14/roll=0，根部单位旋转，经URDF逐关节FK，左/右足底法线相对竖直偏24.67°/13.13°。这是验证“默认角不代表平脚”的构造例子，**不是当前行走实测足倾角，也不能证明初始化姿态造成抖动**。

建议稳定支撑期约束脚部roll/pitch角速度；足面姿态应参考局部支撑面并留容差，允许正常触地、离地和摆腿。不能在波浪、斜面、障碍上强制所有脚始终世界水平。

### 3. 目标限位是软成本，现有目标经常越出硬限位

动作配置 `env_cfg.py:98` 未设clip，普通位置动作执行 `q_des=q_default+scale*a`；`agent_cfg.py:61` 的NormalDist没有有界输出变换。目标soft limit成本先除整个角度跨度再平方，不保证目标可达。

Combined95000快走目标超出URDF硬限位的比例（pitchL/rollL/pitchR/rollR）为 **24.0% / 42.0% / 26.58% / 43.83%**，实际关节角几乎未超硬限位。承载时PD需要位置误差产生力矩，所以目标越限不自动等于bug或撞限位；直接裁剪也可能损失支撑扭矩。应进一步关联越限、实际接近限位和接触冲击，再决定目标范围。

### 4. AMP不直接观察踝稳定性

`tasks/t800_base/constants.py:73–77` 显式排除了四踝；`env_cfg.py:180–216` 判别器输入为命令、根重力方向和其余关节位置/速度，没有足部姿态/角速度。虽然MotionReference的link列表含ANKLE_ROLL，这不代表其足部信息进入AMP。

因此既不能指望AMP自动学会踝消抖，也缺乏“AMP直接学了参考踝抖动”的依据。恢复踝AMP前必须检查示范踝轨迹质量，不能直接解除mask。

## 官方代码能提供什么

- 官方AMP物理步2ms、decimation5，即策略100Hz；当前5ms、decimation4，即50Hz。官方AMP还配置执行延迟及PD随机化，当前不是同一控制条件。更细物理步是值得单独验证的数值基线，但本轮未测试更细dt，也未测试100Hz现有策略；不能直接改变LSTM策略时基。
- 官方地面restitution使用默认0、combine=multiply，配置预期有效恢复系数0；当前地面显式1，会保留机器人0–0.4的随机恢复系数。上轮归零对照没有明显消抖，因此不是现成答案。
- 官方没有发现可直接移植的踝速度低通、目标硬限幅或足部世界姿态奖励。其feet_slide−0.1、feet_air_time+1、全关节acc−1e−8、raw action一阶−0.01/二阶−0.0001，并非“官方已经有很重的踝消抖奖励”。

官方引用：`tasks/locomotion/amp/amp_env_cfg.py:96–106,127–159,258–289,365–417,448–455`；`config/t800/flat_amp_env_cfg.py:61–71`；`mdp/noise.py:57–61`。

## 对下一次改进的建议

优先验证一组目标明确的修改：保留合适的目标平滑，候选踝PD40/2.0，明确机器人与地面的接触参数；新增200Hz物理子步统计的实际稳定性代价，以及稳定支撑期足部roll/pitch转动约束。足部姿态惩罚要有地形与接触阶段条件。不要把旧默认姿态项简单放大很多倍。

权重按实际贡献校准，逐级提高；可以先让实际稳定性成本达到跟踪奖励的几个百分点作为实验起点，而非凭−0.01、−1之类表面数字判定严厉程度。这是实验设计建议，不是已验证最优比例。验收同时观察实际踝/足部高频、跟踪、抬脚/滑脚、跌倒及地形通过率，防止策略用停止走路来少受罚。

现有证据没有证明“续训一定改不过来，只有从头训”。在耗费完整长训之前，应先验证改后的奖励实际有值、PD与接触值正确，以及短续训是否出现方向一致的改善。是否最终从头训练，应由这些对照决定。

旧固定目标站立试验有8次终止，不能用作“已排除策略、证明纯PD问题”的证据。仿真闭环对照也不是电机台架辨识，真机执行与仿真仍需另外核对。
